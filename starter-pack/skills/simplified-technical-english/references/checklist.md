# STE pre-ship checklist

Run this pass on a finished document before you ship it. Fix every ❌.

## Sentences
- [ ] Every procedure sentence ≤ 20 words; every descriptive sentence ≤ 25.
- [ ] One idea per sentence. No sentence chains two instructions with "and".
- [ ] Active voice throughout. No passive except where the actor is genuinely unknown.
- [ ] Present tense for descriptions; imperative for instructions. No "should/would/could".

## Words
- [ ] One term per concept, used consistently (grep the doc for synonym pairs: folder/directory, get/fetch/retrieve).
- [ ] No term used for two different concepts.
- [ ] Every abbreviation defined once at first use, then used consistently.
- [ ] Wordy phrases replaced (in order to → to, due to the fact that → because).
- [ ] Vague words replaced with concrete facts (quickly → within N seconds).
- [ ] No "basically / simply / just / of course / please note".

## Structure
- [ ] Procedures are numbered; one action per step; each step starts with an imperative verb.
- [ ] Conditions come before actions ("If X, do Y").
- [ ] Warnings/cautions appear before the step, structured condition → consequence → action.
- [ ] Lists are grammatically parallel (all imperative, or all nouns).
- [ ] No noun cluster longer than 3 words.

## Reference clarity
- [ ] Every pronoun (it/this/they/these) has exactly one possible referent. If not, repeat the noun.
- [ ] A non-native English reader could parse each sentence one way only.

## Final read
- [ ] Read each instruction as if executing it literally. Does it work with no guessing?
- [ ] Nothing tells the reader only what NOT to do without also telling them what to do.
